-------------------------------------------
DONE TODAY:
- Removed a real leak: auth.js had a code comment with the password in plain
  text (// sha256("...")). Deleted it. "View source" no longer shows it.
- Hardened the stored credential: instead of a plain SHA-256 (trivially cracked
  for a short numeric password via lookup sites), it's now a SALTED, KEY-STRETCHED
  hash — salt + 2000 rounds of SHA-256 (hashPassword() in auth.js). Inspect now
  shows only a salted hash that rainbow tables can't reverse. Login adds ~0.2-0.4s
  (one-time) which is fine. Still synchronous so it works from file://.
- Redacted the plaintext password from PROGRESS.txt (it is a public repo / the
  file is also served by Pages).
- Cache-busters bumped v10 -> v11 so the old auth.js (with the leak) can't stay
  cached in anyone's browser.

HONEST LIMITS (told Nimith):
- This is still a SOFT gate. A determined person can bypass it client-side
  (e.g., set the sessionStorage flag or read the page markup) regardless of how
  the password is stored. Snooping for the password via inspect is now defeated;
  true protection still requires backend auth (server/index.js) so the password
  and the protected content never reach the browser.
- The password also still exists in earlier git history. Removing that needs a
  history rewrite, or simpler: change the password (and ideally go backend).
